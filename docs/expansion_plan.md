# Post-acceptance expansion plan

The accepted local product is complete within its public-data scope. Future work should remain evidence-driven and separately authorized.

## Near-term public-data maintenance

- Refresh source vintages and verify schema drift.
- Re-run clean initialization, tests, storage checks, sample analyses, and QA after material source changes.
- Improve English metric labels in machine-readable configuration while retaining Chinese localization resources.
- Add a compact, redistribution-cleared demonstration snapshot only if every included upstream term permits it.

## Gated integrations

- Activate commercial mobility only after lawful access, aggregation, retention, privacy, and reporting rights are documented.
- Activate commercial real-estate feeds only after the operator supplies permitted files and contractual rights.
- Add NJ TRANSIT, CTtransit, or PATH only after credentials and license requirements are explicitly satisfied.

## Scoring research

Do not enable an overall site score until the operator provides a sufficient set of completed projects, a defined outcome, temporal holdout criteria, bias review, and a reviewed model card. Until then, expose raw metrics, classifications, confidence, and limitations only.

## Scale threshold

Keep DuckDB and partitioned Parquet until measured workload demonstrates that concurrent access, update frequency, or query latency requires a service database. Any migration should preserve snapshot and evidence lineage.
